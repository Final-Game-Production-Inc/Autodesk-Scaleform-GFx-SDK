# 技术方案与实验计划 · VKFILTER

> 原则：**先取证，再假设**。每个实验必须能在**不改渲染逻辑**的前提下回答一个问题；
> 一次只改一个变量；结论必须带证据（日志/BMP/截图/计数）。

---

## 1 假设清单

| ID | 假设 | 支持证据 | 反证/判据 | 优先级 |
|---|---|---|---|---|
| **H1** | 描述符池/UBO ring 容量不足，导致 draw 静默失败（`Finish` 里 `vkAllocateDescriptorSets` 失败后直接 `return`） | 当前 `SF_VK_DESCRIPTOR_POOL_MAX_SETS=2048`（D01），每 draw 分配 1 个 set；UBO 溢出则 `return 0`（D02） | 统计分配失败次数/每帧 set 数/UBO 峰值。**按现有探针估算每帧仅 10–30 次 `Finish`，离 2048 与 8 MiB 都远 → 可能性中低**，但失败是静默的，必须用 E4 一票否决 | ★★ |
| **H2** | 滤镜的中间 pass 实际没有写进临时 RT（内容为空），合成只是把"空"搬上屏 | 黑屏且无校验错误；历史上有过 pass 内 pipeline/pass 不匹配的记录 | 回读中间 RT：始终全 0 则成立 | ★★★ |
| **H3** | 合成 quad 的 texgen/blend/mvp 使输出为不透明黑，或覆盖范围远大于滤镜区域 | `[VKCOMP2]` 只验证了参数非 0，没有验证语义；"整屏黑"无法用 100×164 的小区域解释 | 逐 filter 记录 area/mvp/覆盖像素；回读合成前后 | ★★★ |
| **H4** | 临时 RT 从 `COLOR_ATTACHMENT_OPTIMAL` 到 `SHADER_READ_ONLY_OPTIMAL` 的过渡/可见性有问题，采样到 0 | 离屏 pass 声明 `finalLayout=SHADER_READ_ONLY_OPTIMAL`（理论上正确） | 校验层为 0 且 layout 声明正确 → 可能性中低；可用 `vkCmdPipelineBarrier` 显式过渡验证 | ★★ |
| **H5** | 滤镜 shader 的 UBO 字段布局（`Location`/`Size`/`ShadowOffset`）与 SPIR-V 实际不一致，uniform 写到了错误偏移 | `Finish()` 用 `Location*16` 当字节偏移写 UBO（`Vulkan_Shader.cpp:266/282`），这是**强假设**：只有 std140 且每字段 16 字节对齐时才成立 | `spirv-dis` 反汇编核对 member offset；或把 UBO 内容 dump 出来与期望值比对 | ★★ |
| **H6** | 多 pass ping-pong（`Alg::Swap(Source,Dest)` + `Target_Original`）在 Vulkan 下引用错目标（例如合成采样了"源"而不是"最后一遍输出"） | `Render_ShaderHAL.h:200-275` 的通用逻辑；D3D11 正常说明逻辑本身对 | 回读每个 pass 输出，确认合成时 `tex0` 指向的是最后一个 pass 的结果 | ★★ |
| **H7** | `FilterPrimitive` / `FilterSet` 生命周期问题残留（历史崩溃已修，但仍有提前释放/复用） | 历史上在 Vulkan 上出现过 `~FilterSet` 崩溃，根因是 `Texture` 未摘链（已修） | 加毒化/哨兵后无异常则排除 | ★ |
| **H8** | 某个 FilterType 的 shader 组合没有对应 pipeline，`GetPipeline` 返回 `VK_NULL_HANDLE` 后沿用上一个 PSO → 画错/画黑 | `[VKFIN]` 验证了 shader 非空，但**没有验证 `GetPipeline` 返回值非空** | 在 `GetPipeline` 返回处统计 NULL 次数与对应 Type | ★★ |

> H1 与 H2/H3 不是互斥的：容量问题可能造成"部分 draw 丢失"，表现为局部花屏；而"整屏纯黑"
> 更像 H2/H3。M1 先用 E1/E4 把 H1 与 H2/H3 分流。

## 2 实验设计

### E1 · 交换链终帧回读（判定"黑"的性质）

| 项 | 内容 |
|---|---|
| 目的 | 区分：①屏幕上确实被画了黑；②本帧内容根本没进交换链/呈现了别的图；③窗口层问题 |
| 做法 | 给 swapchain 增加 `VK_IMAGE_USAGE_TRANSFER_SRC_BIT`（先查 `supportedUsageFlags`）；在 `presentFrame()` 的 `vkEndCommandBuffer` 之前插入：`PRESENT_SRC_KHR → TRANSFER_SRC_OPTIMAL` barrier → `vkCmdCopyImageToBuffer`（host-visible buffer，`rowPitch=width*4`）→ 还原 layout。只在 `GFX_VK_DUMP_SWAP=<frame>` 指定的帧执行一次，dump 为 BMP |
| 预期 | 若回读图 = 灰底（0x55）或部分内容 → 屏上黑来自呈现之后/窗口层，方向改为查 present/swapchain；若回读图 = 纯黑 → 内容确实被画黑，进入 E2/E3 |
| 成本 | 0.5 人日（含一个 20 行的 BMP dump 工具） |
| 风险 | 驱动不支持 `TRANSFER_SRC`（低）；`rowPitch` 对齐错误会得到斜图（用 `vkGetImageSubresourceLayout` 或按 4 字节对齐即可） |
| 产出 | `artifacts\swap_<frame>.bmp` + 一行日志 `[VKFILTER:swap] img=%u frame=%u` |

### E2 · 按 FilterType 二分（把"全开"压到"单一类型"）

| 项 | 内容 |
|---|---|
| 目的 | 找出"哪个滤镜类型一开就黑"，缩小到具体 shader 组合 |
| 做法 | 新增启动时解析的 `GFX_VK_FILTER_ALLOW=shadow,blur,glow,...`（逗号分隔，空=全部允许）。`shouldRenderFilters(prim)` 遍历 `prim->GetFilters()`，**只要有一个类型不在白名单就返回 false**。一次构建，多次运行 |
| 矩阵 | ① shadow ② blur ③ glow ④ bevel ⑤ gradientGlow ⑥ gradientBevel ⑦ colorMatrix ⑧ displacementMap ⑨ 全开（对照组） |
| 记录 | 每种组合：alive 时长、是否黑屏、stderr 行数、截图；同时打印每个 filter 的 `type / area / mvp / 覆盖像素估算` |
| 预期 | 若某单一类型即黑 → 直接锁定该类型；若全部单类型都正常、只有组合黑 → 指向 pass 链/ping-pong（H6）或容量（H1） |
| 成本 | 0.5 人日（1 次构建 + 9 次运行，单次 ≤ 30s） |
| 产出 | 二分矩阵表 + 每种组合的截图 |

### E3 · 中间 RT 回读（定位"哪一步开始变黑"）

| 项 | 内容 |
|---|---|
| 目的 | 回答：源 RT 有没有内容？第几遍 pass 之后变成全 0？合成时采样的是哪一个？ |
| 做法 | ① 给临时 RT 的 image 增加 `TRANSFER_SRC` 用法（`Vulkan_Texture.cpp` 的创建路径，按 `RBuffer_Temporary` 判定）；② 在 `PopRenderTarget()` 中 `vkCmdEndRenderPass` 之后、恢复主 pass 之前插入 `SHADER_READ_ONLY_OPTIMAL → TRANSFER_SRC_OPTIMAL` barrier + copy + 还原；③ 文件名 `rt_f<frame>_p<pass>_t<filterType>.bmp`；④ 只对 `GFX_VK_DUMP_RT=<frame>` 的帧执行 |
| 预期 | 三类结果，分别对应 H2/H6/H3（见 §4 决策树） |
| 成本 | 1.0 人日 |
| 风险 | 给所有临时 RT 加 `TRANSFER_SRC` 可能影响内存/性能（仅调试构建开启，用宏隔离） |
| 产出 | 一串按 pass 排序的 BMP + 一行 `[VKFILTER:rt] frame=… pass=… type=… tex=…` |

### E4 · 容量审计（验证 H1）

| 项 | 内容 |
|---|---|
| 目的 | 确认当前 2048 池 / 8 MiB UBO ring 是否在 9-1-B 开滤镜时被打满 |
| 做法 | 在 `Finish()` 统计每次分配（成功/失败）与 `uboOffset`，在 `BeginFrame` 归零、`EndScene` 打印一行：`sets=%u fail=%u uboMax=%llu draws=%u`；失败时额外打 `[VKFILTER:setfail] type=…` |
| 判据 | `fail>0` 或 `sets > 2048` → H1 成立；此时先回填 D01/D02（8192 + 安全回绕）再重测，避免"修容量的收益"与"滤镜根因"混在一起 |
| 成本 | 0.2 人日 |
| 产出 | 每帧一行计数 + 峰值统计 |

### E5 · 滤镜 shader 的 UBO/binding 核对（验证 H5）

| 项 | 内容 |
|---|---|
| 目的 | 确认 `Location*16` 当字节偏移的写法对滤镜 shader 成立 |
| 做法 | 用 Vulkan SDK 的 `spirv-dis` 反汇编滤镜 FS/VS（从 `Vulkan_ShaderBinary.cpp` 的 blob 导出，或直接用 ShaderMaker 的中间产物）；核对 `binding` 编号、UBO member 的 `Offset`/`Size`、纹理数组维度；与 `Vulkan_ShaderDescs.*` 的 `Uniforms[i].Location/Size/ShadowOffset` 逐项比对 |
| 判据 | 任意一项不一致 → H5 成立，且能解释"uniform 全 0 / 采样坐标错"导致的黑 |
| 成本 | 0.5 人日 |
| 产出 | 对照表（shader 侧 vs 代码假设） |

### E6 · 参考实现对齐（R2）

| 项 | 内容 |
|---|---|
| 目的 | 若参考实现（`H:\SDKS\UI SDKS\timbreunda vulkan`）的滤镜能正常工作，则本工程的"扩展"里有 bug |
| 做法 | 先确认参考树能否独立构建并跑 9-1-B；能则对比同帧截图；不能则只做**源码级**对齐（已知差异：`Vulkan_HAL.cpp` 93/5 行、`Vulkan_HAL.h` 64/0、`Vulkan_Texture.cpp` 61/11、`Vulkan_Sync.h` 65/42） |
| 判据 | 参考实现正常 → 用"逐条加回"的方式二分本工程扩展；参考实现也黑 → 说明是 Scaleform 共享层在 Vulkan 上的语义问题，转向 E5/共享层 |
| 成本 | 1.0 人日（含构建排查） |
| 风险 | 参考树可能缺依赖/配置，构建成本不可控 → 超 0.5 人日即降级为纯源码对比 |

### E7 · RenderDoc 抓帧（R3，人工）

| 项 | 内容 |
|---|---|
| 目的 | 一次看到 GPU 真实状态：descriptor set 内容、VS 输出顶点、FS 采样 UV 与返回颜色 |
| 做法 | RenderDoc 启动 `GFxPlayer_Vulkan_Debug_Static.exe`，滤镜开，抓一帧；在 Event Browser 里定位滤镜的 draw，看：①绑定的 descriptor set（binding 2/3 是否指向临时 RT）；②Mesh Viewer 的 VS Input/Output；③Pixel History 的 UV 与采样结果 |
| 判据 | 与 E1/E3 的回读结果互相印证；若两者矛盾，以 RenderDoc 为准 |
| 成本 | 0.5 人日（不计安装） |
| 依赖 | 本机需安装 RenderDoc；需要人眼判读 |

### E8 · 生命周期毒化（验证 H7，低优先）

| 项 | 内容 |
|---|---|
| 目的 | 排除 `FilterPrimitive`/`FilterSet` 提前释放 |
| 做法 | 释放时把对象填 `0xDD`，在 `drawUncachedFilter` 入口校验 `filters->GetFilterCount()` 合理性与指针可读性 |
| 判据 | 出现毒化特征 → H7 成立；否则关闭该方向 |
| 成本 | 0.5 人日 |

## 4 决策树

```
T05 复现（当前源码，全量重编）
├─ 不复现"黑屏"（崩溃/断言/正常）
│   └─ 基线漂移（D01/D02/D06）→ 先对齐基线、记录差异 → 重新进入本树
└─ 复现
    ├─ E4: sets>2048 或 fail>0 ?
    │   └─ 是 → 回填 D01/D02 → 重测
    │        ├─ 恢复 → 根因=容量（H1），继续验证滤镜全类型
    │        └─ 仍黑 → 继续
    └─ E1: 交换链终帧是纯黑 ?
        ├─ 否（有灰底/部分内容）→ 查 present/swapchain/窗口层（非本专项主路径，先记录）
        └─ 是
            ├─ E2: 单一 FilterType 就复现 ?
            │   ├─ 是 → 锁定该类型，进 E5（shader/UBO）与该类型的 pass 链
            │   └─ 否（只有组合/全开黑）→ 进 E3
            └─ E3: 哪一步开始全 0 ?
                ├─ 源 RT 就是黑 → "把场景渲染进 RT"这一段：Push/Pop、viewport、mvp、blend
                ├─ 中间 pass 后变黑 → 该 pass 的 shader/UBO/blend/pipeline（E5/E7）
                └─ 中间有内容、合成后黑 → 合成 quad：texgen/blend/覆盖范围（E7 为主）
```
