## 1 构建

### 1.1 常规构建

```bat
taskkill /IM GFxPlayer_Vulkan_Debug_Static.exe /F 2>nul
taskkill /IM MSBuild.exe /F 2>nul
taskkill /IM mspdbsrv.exe /F 2>nul

MSBuild "Projects\Win32\Msvc18\SDK\GFx 4.5.32 Leslie Demo.slnx" ^
    /t:Build /p:Configuration=Vulkan_Debug_Static /p:Platform=x64 /m
```

- `MSBuild.exe` 位于 VS 安装目录（CheckPoint 记录：`D:\Program Files\Microsoft Visual Studio\18\Enterprise`），
  通常在 `…\MSBuild\Current\Bin\MSBuild.exe`。
- 产物：`Bin\x64\Msvc18\GFxPlayer\GFxPlayer_Vulkan_Debug_Static.exe`
- 中间目录：`Obj\x64\Msvc18\Vulkan_Debug*\…`、`Obj\x64\Msvc18\Vulkan_Debug_Static*\…`

### 1.2 全量重编（改过头文件 / 出现"玄学"崩溃时必做）

```bat
rd /s /q Obj\x64\Msvc18\Vulkan_Debug
rd /s /q Obj\x64\Msvc18\Vulkan_Debug_Static
MSBuild …（同上，建议连跑两遍）
```

仅在确认"混编旧 lib"时（启动即崩、类布局错乱、LNK 找不到符号）：

```bat
del /q Lib\x64\Msvc18\Debug\*.lib
```

> ⚠️ `Lib\x64\Msvc18\Debug` 是**所有后端共用**的目录。D3D12 编出的旧 lib 与 Vulkan 头文件布局不一致
> 会导致启动崩溃（已发生过一次，CheckPoint 22:35）。删之前先确认没有别的后端在用。

### 1.3 常见构建错误

| 错误 | 处理 |
|---|---|
| `LNK1104` 打不开 exe | 有残留进程，先 taskkill |
| `LNK1318` PDB RPC 错误 | 杀 `MSBuild.exe` / `mspdbsrv.exe` 后重试 |
| 失败一次后 exe 消失 | 重新构建即可恢复 |
| `PlayerTiny` 的 `dxgitype.h` 重复定义 | 既有问题，与本专项无关；单独构建 GFxPlayer 即可 |

## 2 运行与复现

### 2.1 基本命令

```bat
set GFX_VK_FILTERS=1
Bin\x64\Msvc18\GFxPlayer\GFxPlayer_Vulkan_Debug_Static.exe ^
  "F:\GFxTest\SWF\People's Music Publishing House With CDs\Grade 5 U\lesson10\listen2\9-1-B.swf"
```

### 2.2 样本

| 代号 | 路径 | 用途 |
|---|---|---|
| J | `F:\GFxTest\SWF\People's Music Publishing House With CDs\Grade 5 U\lesson1\listen1\J.swf` | 无滤镜依赖的基线（按钮/矢量/文字） |
| 9-1-A | `…\Grade 5 U\lesson10\listen1\9-1-A.swf` | 含 DropShadow（小提琴投影） |
| 9-1-B | `…\Grade 5 U\lesson10\listen2\9-1-B.swf` | **主复现样本**；答题后进入反馈动画，历史上最容易触发崩溃 |

### 2.3 9-1-B 答题（进入"顺利通过"状态）

启动后等待 6 秒，对客户区点击 4 行"是/否"，两轮：

```
(429, 333) (429, 423) (429, 514) (429, 604)   ×2
```

参考实现（PowerShell + `PostMessage`，仓库根的 `soak_run3.ps1` 是模板，需改 exe/开关后使用）：

```powershell
[ClkV]::ClickAt($hwnd, 429, $y)   # WM_LBUTTONDOWN/UP，间隔 50ms，两次点击间隔 250ms
```

> 坐标基于 1024×768 客户区；窗口 DPI/缩放变化后需重新标定。

### 2.4 观察时长与退出

- 最短判定：启动 → 12s（是否黑屏/是否崩溃）
- 交互判定：答题后 30s
- 稳定性判定：答题后 60s（AC1）
- 正常退出：`WM_CLOSE` → `exit code = 0`

## 4 崩溃与断言取证

### 4.1 dump 采集

1. WER LocalDumps 已为 `GFxPlayer_Vulkan_Debug_Static.exe` 配置（`dumps\`，full dump）；
2. 断言（`0x80000003`）在 Debug 下会先断到调试器；无调试器时进程直接退出，需靠日志定位。

### 4.2 分析

```bat
cdb -z dumps\GFxPlayer_Vulkan_Debug_Static.exe.<pid>.dmp -c ".ecxr; kb 40"
```

> 不要用 `!analyze -v`（太慢），`kb` 足够。

### 4.3 退出码速查

| 退出码 | 含义 |
|---|---|
| `0` | 正常 |
| `0xC0000005` | AV（历史上多为悬垂指针/堆破坏） |
| `0x80000003` | Debug 断言（如 "render targets still in-use"） |
| `0xCFFFFFFF` | CRT/Debug 运行时强制终止（历史上滤镜路径出现过） |

### 4.4 PageHeap（谨慎）

```bat
gflags /p /enable GFxPlayer_Vulkan_Debug_Static.exe /full
gflags /p /disable GFxPlayer_Vulkan_Debug_Static.exe
```

> CheckPoint 23:55 记录：PageHeap 开启时 Vulkan 曾出现"启动即崩"，影响判定。本专项**默认不开**，
> 仅在怀疑堆破坏（随机崩溃、`free_base`、`HeapMH` 栈）时短期开启，用完立即关闭。

## 5 判定标准

| 判定 | 方法 | 记录内容 |
|---|---|---|
| 是否存活 | 启动后 N 秒 `MainWindowHandle != 0` 且进程未退出 | `alive@Ns` |
| 是否黑屏 | 窗口客户区截图，统计非背景像素比例 | `black%`（纯黑占比） |
| 是否崩溃 | 退出码 + stderr 最后 20 行 | exit code、末行 |
| 是否有校验错误 | stderr 过滤 `VUID` / `Validation Error` / `VK_ERROR` | 条数 + 首条 |
| 是否视觉正确 | 与 D3D11 同状态截图对比（AC2） | diff 图、差异面积 |
| 是否资源归位 | `EndFrame` 断言、live object 计数 | 条数 |

**基线三件套**（每次实验必须记录）：`exe 时间戳` + `stderr 全文` + `截图`。

## 6 环境坑（都是踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| 任何 Vulkan 程序都跑不起来（含未改动的备份） | 反复 device lost 后驱动进入异常状态 | **重启机器**（已发生两次） |
| 启动即崩、栈在 `ConstructAlt` / 类布局 | `Lib\x64\Msvc18\Debug` 混着别的后端的旧 lib | 删 lib + Obj 全量重编 |
| 改了头文件后行为"玄学" | 增量编译没重编依赖 TU，ABI 不一致 | 删 Obj 全量重编（D3D12 时期的教训） |
| `LNK1104` 打不开 exe | 上次的 player 还在跑 | taskkill |
| 窗口黑但日志正常 | 可能正是本专项的问题 | 走 E1 判定，不要猜 |
| 断言"render targets still in-use" | 临时 RT 未归还 | 查 `PendingRTReleases` 的入队/出队配对（`Vulkan_HAL.cpp:259-314`） |
