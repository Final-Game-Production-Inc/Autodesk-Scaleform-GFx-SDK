## 1 立项背景

### 1.1 已完成的部分

Vulkan 后端在 2026-10-28 上午完成了一轮集中攻坚，当前可用状态（CheckPoint 10:20–12:15）：

- 启动崩溃（`Lib\x64\Msvc18\Debug` 混编旧 lib）→ 已解决
- GPU 校验层报错（深度/模板 `initialLayout` + 首帧 barrier、WRITE_AFTER_WRITE）→ 清零
- 帧槽号错位（`beginFrame` 用 A 槽、`presentFrame` 用 B 槽）→ 已修
- `GetFilterPasses` 栈溢出（`passCount-1` 下溢导致 40 亿次循环写穿栈）→ 已修（D3D11/D3D12 同受益）
- `Texture::~Texture()` 未 `RemoveNode()`（与 D3D12 同源）→ 已修，悬停崩溃消失
- 资源回收时机（`DrainFrameResources` 移到 `vkWaitForFences` 之后）→ 已修，device lost 消失
- 无滤镜路径：`J.swf` / `9-1-A.swf` / `9-1-B.swf` 全部正常渲染，`exit=0`

**结论：Vulkan 后端除滤镜外，已达到"可交付、可演示"的状态。**

### 1.2 唯一未完成的一块

滤镜（filter）路径开启后 `9-1-B.swf` **整屏黑**，且：

- 校验层 **0 条报错**（API 用法合法，不是非法调用）
- 12 个结构性原因已逐一排除（见 [02](02_现状与证据链.md) §2）
- 历史上还伴随过 `RenderBufferManager::EndFrame` 的 "render targets still in-use" 断言、
  `ShaderInterface::Finish` 崩溃、device lost —— 现在（11:45 基线）表现为"黑屏但不崩"

当前为交付采取的临时策略：`Vulkan::HAL::shouldRenderFilters()` 默认返回 `false`，
仅 `GFX_VK_FILTERS=1` 时才渲染滤镜（`Src\Render\Vulkan\Vulkan_HAL.cpp:1134`）。

### 1.3 为什么单独立项

1. **问题自包含**：坏点只在 filter 路径，普通绘制（文本/矢量/位图/遮罩/渐变）全部正常。
   混在主线里"顺手修"会反复打断主线交付节奏。
2. **需要独立工具与开关**：GPU 侧取证（交换链 / 临时 RT 回读、按 FilterType 二分、
   逐 pass 截图）需要一套专用调试设施，不适合塞进主线代码。
3. **失败不影响交付**：滤镜默认关闭时主线可用。专项失败只回退到"按类型白名单"，
   不存在阻塞风险，因此可以按"限时攻坚"的方式管理。
4. **已有沉没成本需要固化**：12 项排除、7 组探针数据、若干次无效尝试都记录在 CheckPoint 里；
   不立项就没人负责把它们转成"不再重复踩坑"的资产。
5. **同源问题可复用结论**：D3D12 的 filter 多 pass 同样未完成（目前只开 `Filter_Shadow`），
   本专项的方法论与工具将来可直接复用（但 D3D12 修复另立，见 §4 非目标）。

## 2 问题陈述

### 2.1 现象

| 场景 | 期望（D3D11 同状态） | 实际（Vulkan，滤镜开） |
|---|---|---|
| `9-1-B.swf` 进入答题页 | 题目文字、是/否、红勾、树、角色、音符、渐变横幅全部可见 | **整屏黑**，无任何内容 |
| `9-1-A.swf`（含投影滤镜） | 小提琴白色投影 | 滤镜关闭时正常（无投影）；滤镜开启无黑屏 |
| `J.swf`（无滤镜依赖） | 正常 | 正常 |

### 2.2 复现

```
GFX_VK_FILTERS=1
Bin\x64\Msvc18\GFxPlayer\GFxPlayer_Vulkan_Debug_Static.exe ^
  "F:\GFxTest\SWF\People's Music Publishing House With CDs\Grade 5 U\lesson10\listen2\9-1-B.swf"
```

- 启动即黑（不需要答题；答题只是历史上更容易触发崩溃/断言）
- 关闭滤镜（不设该环境变量）同一文件完全正常
- 详细步骤、点击坐标、判定标准见 [04_复现与调试手册.md](04_复现与调试手册.md)

### 2.3 影响面

- **视觉**：所有依赖 filter 的效果缺失（投影、模糊、发光、渐变发光、颜色矩阵、置换贴图），
  与 D3D11 的观感不一致；教学类 SWF 的"渐变文字 + 遮罩"会退化成纯色块或消失。
- **交付**：Vulkan 后端只能以"滤镜关闭"的形态交付，属于**已知限制**。
- **技术债**：`Render_ShaderHAL.h` / `Vulkan_HAL.cpp` 里仍留有多处 `GFX_VK*` 探针，
  长期留在热路径上会拖慢每帧（`Finish()` 内每次 draw 调 `getenv`）。

### 2.4 已确认不成立的解释（摘要，详见 02）

缺 shader / pipeline 未绑定 / 临时 RT 未建立 / 恢复主 pass 清屏 / 纹理未绑定 /
帧缓冲与呈现图像错配 / 走了 cached 路径 / PerDraw 顶点流未绑定 / `SetFilterFill` 缺实现 /
`Location` 与 binding 基准不一致 / 合成矩阵或纹理参数错误 / 顶点格式 f32-vs-i16 错配。
**这 12 条都不成立**，因此本专项不能再从这些方向入手。

## 6 技术路线

### 6.1 三条候选路线

| 路线 | 做法 | 成本 | 信息量 | 风险 |
|---|---|---|---|---|
| **R1 数据驱动**（主力） | 交换链/RT 回读 + 按 FilterType 二分 + 逐 pass dump，用"哪一步开始变黑"定位 | 中 | 高（直接看到内容） | 需给 swapchain/RT 加 `TRANSFER_SRC` 用法 |
| **R2 参考实现对齐** | 以 `H:\SDKS\UI SDKS\timbreunda vulkan` 为基线，逐函数回退本工程扩展 | 中 | 中（参考实现未必支持滤镜） | 参考树可能不可构建 |
| **R3 GPU 帧调试** | RenderDoc 抓帧看 descriptor / VS 输出 / FS 采样 | 低（人工） | 最高 | 需本机安装，且无法脚本化 |

**推荐组合：R1 → R3（验证）→ R2（若 R1 无法收敛）。**

### 6.2 核心判断

12 项排除已经把"结构性/绑定类"原因清空，剩下两类可能：

1. **内容问题**：临时 RT 里本来就是黑的（滤镜 pass 没真正写进去），合成只是把黑搬上屏；
2. **合成问题**：内容在 RT 里，但合成 quad 的 texgen/blend/采样把它变成黑或整屏覆盖。

这两类的**分界点是"回读中间 RT"**（E3）。执行顺序上先用 E1 把"整屏黑"的**性质**定下来
（画了黑 / 没进交换链），再用 E3 定位到具体 pass；E1 与 E3 共用同一套 BMP 回读设施。

## 8 工程接入方案（与 .slnx 的关系）

> 用户指定工程：`Projects\Win32\Msvc18\SDK\GFx 4.5.32 Leslie Demo.slnx`
> 现状：`GFxPlayer` 已在该解决方案 `/Demos/Player/` 下，配置 `Vulkan_Debug_Static`（GUID `1804709B-…`），
> Vulkan 相关宏/库由 `Projects\Win32\Property Sheets\GFx_Renderer_Vulkan.props` 统一注入
> （`FXPLAYER_RENDER_VULKAN`、`vulkan-1.lib`、`libgfxplatform_vulkan.lib`、`libgfxrender_vulkan.lib`）。

在不破坏现有构建的前提下，有三种隔离强度可选：

### 方案 A（推荐，M1/M2 使用）—— 不动解决方案，用开关 + 调试模块隔离

- 新增 `Src\Render\Vulkan\VkFilterDebug.h/.cpp`：统一持有所有 `GFX_VK_*` 开关（启动时读一次）、
  回读 dump、类型白名单、逐 pass 计数；仅在 `SF_VK_FILTER_DEBUG` 定义时编译进
  `libgfxrender_vulkan`，默认路径零开销
- 解决方案文件**零改动**；实验代码不进入普通构建
- 优点：M1 立刻可做，构建风险为 0；缺点：与主线同二进制（靠宏隔离）

### 方案 B —— 新增解决方案 BuildType `VulkanFilter_Debug_Static`

- `GFx 4.5.32 Leslie Demo.slnx`：`<Configurations>` 增加一行；每个 `<Project>` 节点增加
  `<BuildType Solution="VulkanFilter_Debug_Static|*" Project="Debug" />`（约 20 处）
- `GFxPlayer.vcxproj`：需要新增完整的 `ProjectConfiguration` + `PropertyGroup` +
  `ImportGroup` + `ItemDefinitionGroup`（4 段，28 个已有配置之外再加 1 个）
- 优点：实验配置与主线并行、互不污染；缺点：改动面大（20+ 处），**在无构建验证的情况下风险高**
- 适用：专项转入长期维护（> 1 周）、需要长期保留两套二进制对比

### 方案 C —— 新增独立工程 `GFxPlayerFilter.vcxproj`

- 位置：`Projects\Win32\Msvc18\SDK\GFxPlayerFilter\`
- 复用 `Apps\Samples\FxPlayer\FxPlayer.cpp`（含 `SF_PLATFORM_SYSTEM_APP` 入口）与
  `Apps\Samples\Common\*`，可加滤镜调试专用入口
- 必须在 slnx `/Demos/Player/` 下注册新 GUID；`OutDir`/`IntDir`/`TargetName` 必须独立，
  否则与 `GFxPlayer` 产物冲突（历史 LNK1104/LNK1105 的常见原因）
- 优点：最强的隔离，可做成长期工具；缺点：成本最高（手写 vcxproj + 注册 + 首次编译排查）

**结论：M1/M2 走方案 A；若 M3 之后仍需长期反复回归，再升级到方案 B。方案 C 仅在"要做成
长期诊断工具"时才值得。**

> 待确认：是否现在就实施方案 B/C。本会话**没有**修改 `.slnx` 或任何 `.vcxproj`——
> 在无法构建验证的情况下改动解决方案，风险大于收益（见 §9 R-03）。

## 10 治理规则

1. **一次只改一个变量**：每个实验一个 ID（E1–E8），一次只动一处，结果记入 03 §7 台账。
2. **改前必备份**：`backup_vkfilter_YYYYMMDD_HHMM\`（只备份被改的目录 + 文档），并在 CheckPoint 记录。
3. **改头文件 = 全量重编**（R-02）；每次实验记录 exe 时间戳。
4. **共享层改动最小化**：优先在 `Src\Render\Vulkan` 内覆写；确实要改 `Render_Shader*.h` 时，
   必须同时跑 D3D11 / D3D12 冒烟（各 1 个 SWF）。
5. **开关规范**：统一 `GFX_VK_*` 前缀、默认关闭/默认安全值；**热路径禁止 per-call `getenv`**（AC7）。
6. **日志规范**：统一 `[VKFILTER:xxx]` 前缀写 stderr，禁止无前缀散打。
7. **禁止"整份恢复备份"**：必须 diff 出关键修复再合（CheckPoint 11:xx 已有一次因恢复备份
   丢掉 `Texture::~Texture()` 修复、导致 9-1-B 内容丢失的教训）。
8. **每次会话结束**：更新 CheckPoint + 看板 + 备份；把"下次第一件事"写清楚。
