## 1. 概要

D3D12 后端的问题不是"一个 bug"，而是**一条因果链**：

```
D3D12::Texture 析构不摘链（真根因）
   └─ TextureManager::Textures 侵入式链表悬垂
        └─ 下一次 PushBack 踩已释放内存 → Scaleform 堆空闲链被写坏
             ├─ MeshCacheItem::ListType(+24) 被写脏 → RemoveNode 越界写
             ├─ HMatrix 句柄悬垂 → 往 .rdata 默认矩阵写 → AV
             ├─ 随机位置崩溃（Image::releaseTexture / HeapMH::BinNodeMH / …）
             └─ 26 个 live ID3D12Resource、654 描述符洪水
```

这条链修好后，"顺利通过"的**黄色方块**、各处随机 `0xC0000005`、退出崩溃、资源泄漏**同时消失**——它们是同一个病灶的不同表现。

除此之外还有两组独立问题：**GPU 同步/描述符/命令列表**（设备挂起、Debug Layer 6 类报错）和**顶点格式映射**（矢量与描边画到看不见的地方），以及**视频/音频**的一整套移植缺陷。

## 3. 根因与修复

### R1 帧内释放了命令列表还在引用的 staging 资源（P1 的主因）

`TextureManager::BeginScene()` 每个 scene 都 `PendingStagingRelease.Clear()`；而纹理上传的 staging buffer 是在 `Texture::CommitImageUpload()`（第一次 `ApplyTexture`）才挂上去的。同一个 frame 的第二个 scene 一开始就把 staging 资源释放，而 `CopyTextureRegion` 仍引用它 → id=921 → GPU 读已释放显存 → TDR。

**修复**：把"上一帧资源回收"整段从 `BeginScene()` 移到新增的 `TextureManager::BeginFrame()`（平台在 `Device::BeginFrame` 里已等过帧栅栏）。

### R2 mesh cache 的 GPU 栅栏永远不是 pending

`RenderSync::SetFence()` 原来**立刻** `pCommandQueue->Signal()`，但绘制命令还在录制中（命令列表要等 Present 才 Execute）。于是 `IsPending()` 立刻返回 false，`MeshCache::Evict()` 认为顶点/索引 buffer 可复用，`MeshCache::EndFrame()` 直接 delete（MeshBuffer 析构会 Release `ID3D12Resource`）。

**修复**：`SetFence()` 只记录待发信号；新增 `RenderSync::FlushPendingSignals()`，由 `Platform_D3D12::presentFrame()` 在 `ExecuteCommandLists` 之后调用。

### R3 描述符表只写了一半 + sampler scratch 覆盖整个堆

根签名声明 `t0..t7 / s0..s7`，但 `bindStageTextures()` 只 copy 实际绑定的 1~2 个 stage，其余 6 个是未初始化描述符（shader 读到垃圾，属 UB）。另外 `SamplerScratchDescriptorCount` 与 `D3D12_SamplerHeapDescriptorCount` 都是 1024、scratch 起点为 0，与持久 sampler 状态重叠。

**修复**：每次 draw 都铺满 8 个 SRV（空 stage 复用第一个有效 stage），加"同一组纹理不重复 copy"缓存；sampler 改为每种 fill mode 预建 8 个连续 sampler，彻底不再 per-draw copy；删除 scratch 并在构造时断言不越界。

### R4 命令列表生命周期

`InitHAL` 期间 HAL 会记录 `OMSetRenderTargets`/`Clear`，但命令列表那时是 Close 状态（id=544 "not closed"）；下一帧 Reset 分配器时列表还没关闭（id=543）。

**修复**：创建后保持 Open，`InitHAL` 末尾 Close；`beginFrame` 的栅栏等待从 `FrameFenceValue>1` 改为 `>0` 且等待当前值。

### R5 退出崩溃 0x87D（P3）

Debug Layer 原话（加 `SetName` 后可见资源名）：

```
An ID3D12Resource object (…:'GFx_SwapBuffer0') is referenced by GPU operations
in-flight on Command Queue. It is not safe to final-release objects that may have
GPU operations in-flight.
```

**修复**（`shutdownGraphics()` 顺序）：① 等 GPU + Reset/Close 命令列表清掉录制引用；② `pHal->ShutdownHAL()`；③ `destroySwapChain(true)` —— final teardown 专用路径，Detach `pSwapChain / pRTVHeap / pSwapBuffers`，交给进程退出回收（正常 resize 仍走原逻辑）。**代价**：退出时有意"泄漏"这几个引用。结果：`exit code 0`（原 2173）。

### R6 顶点格式映射：矢量/描边不可见（P4）

两个叠加错误：

1. `MapVertexFormat()` 把 position 从 S16 提升为 F32，但偏移补偿是**死代码**（先 `|= VET_F32` 再判断 `==VET_S16`，永远为假）→ 后续属性 offset 不 `+4`，声明的布局与数据不符；
2. 把 batch/instanced 输出格式**强行替换**成 single（注释写着 "not wired up yet"），而 D3D12 shader 实际支持这些批量格式。

**修复**：先记录原始 compType/size 再改属性并补偿 offset；`*batch / *instanced` 改用 `Base::MapVertexFormat` 返回的真实批量格式（缺失才回退 single）。

效果：J.swf 三个矢量按钮（圆角矩形 + 2.5pt 白描边 + 内嵌字体字母）恢复；9-1-A 提示文字、"小提琴"标签；game02 底部 `2/4 3/4 4/4` 拍号恢复。

### R7 "黄色方块"其实是脏构建 / ABI 不一致（P5 的假象）

与 12:03 的 `D3D12-Bak` 快照逐文件 diff：功能差异**只有** stencil ref 一段；崩溃与黄块都与之无关。真因是 `D3D12_HAL.h` 加了成员后，增量构建没有重编 `Platform_D3D12.obj` 等 TU → 两边对 `D3D12::HAL` 的成员偏移不一致 → HAL 对象被写坏 → 渲染线程堆损坏 + stage/描述符状态读错，表现为"黄色渐变矩形盖住文字"。

**修复**：删掉 `Obj\x64\Msvc18\D3D12_Debug\Render_D3D12`、`…\D3D12_Debug_Static\{Platform,GFxPlayer}` 后重编 —— "顺利通过！"直接恢复正确。

> 规则：**改 `D3D12_HAL.h` / `D3D12_Texture.h` 的类成员后必须删 Obj 重编**，否则 ABI 不一致，症状是"玄学渲染错误 + 堆损坏"。

### R8 连锁崩溃：MeshCache 越界 / HMatrix 悬垂句柄（P6 的表现层）

- **MeshCache**：`MeshCacheListSet::RemoveNode()` 用 `Slots[p->ListType]`，当 item 的 `ListType(+24)` 被写脏则越界写，把 MeshCache 对象写坏（PageHeap 抓到的第一栈：`RemoveNode <- MoveToCacheListFront <- PrimitivePrepareBuffer::ProcessPrimitive`）。**修复**：`RemoveNode` 增加 ListType 范围检查，越界时告警并只清 `pPrev/pNext`。
- **HMatrix**：`ComputeFinalMatrix` 里句柄已被回收/复用，`SetMatrix2D` 往 `.rdata` 的 `HMatrix_DefaultMatrixData` 写 → AV。**修复**：`HMatrix::IsHandleValid()`（SEH 校验 `pHeader` 的 RefCount/UnitSize/Format）+ `SetNull()`；`ComputeFinalMatrix` 写前检测，失配则打印并重建。另在 `SetMatrix2D` 加 SEH 写保护（把"随机堆损坏"变成一条可定位日志）。

这两处是**兜底**，不是根因；根因见 R9。

### R9 真根因：`D3D12::Texture` 析构不摘链、不释放资源（P6 的总源头）

对比 D3D1x 与 D3D12 的析构：

```cpp
// D3D1x
Mutex::Locker lock(&pManagerLocks->TextureMutex);
if (State == Valid || State == Lost) { RemoveNode(); pNext = pPrev = 0; ReleaseHWTextures(); }

// D3D12（修复前）
SF_HEAP_FREE(this, pTextures);   // 既不摘链，也不释放资源
```

后果链：每个销毁的 Texture 都留在 `TextureManager::Textures` 链表里 → 下次 `postCreateTexture → PushBack()` 踩已释放内存（game02 的稳定复现栈）→ 堆空闲链被写坏 → 之前所有"随机崩在不同地方"的连带反应；同时 D3D 资源永不释放（26 live objects、654 洪水）。

**修复**：析构里 `RemoveNode(); pNext = pPrev = 0;`。
**注意**：把 `ReleaseHWTextures()` 放进析构会让 9-1-B 空闲崩溃（试过），所以**只摘链**，资源交给 kill list；随后确认 `D3DTextureKillList` 无重复入队，再恢复 `processTextureKillList()` 真正 Release —— live objects 归 0。

> 同一缺陷后来在 Vulkan 复现（CheckPoint 2026/10/28 01:05：`Vulkan_Texture.cpp` 同样没 `RemoveNode()`，表现为鼠标悬停崩溃）。两个后端同源。

### R10 视频与音频（P7/P8）

| 子问题 | 根因 | 修复 |
|---|---|---|
| 绿屏 | `Texture` 构造函数漏 `TextureCount = pformat->GetPlaneCount()`（YUV 三平面只建了 Y） | ctor 补平面数 |
| 绿屏 | `PrepareImageUpload()` 白名单只允许 RGB/BGRA…，YUV 从不 Decode/上传 | 去白名单，按平面循环 |
| 卡顿 | 每帧 `CommitImageUpload()` 把 staging 推进 `PendingStagingRelease` 并 Clear → 720p 视频每秒 180 次资源创建/销毁 | 每平面两个 staging buffer 轮换，只创建一次 |
| 退出崩溃 | `TextureManager::ImageUpdates` 未排空就拆纹理 → 二次释放 | `Reset()` 里先 `ImageUpdates.ProcessUpdates(this)` |
| 开头绿帧 | 首帧未到时 `Decode()` 失败 → staging 全 0 → YUV(0,0,0)=亮绿 | 首次失败填 YUV 黑（Y=16,U=V=128）；无纹理分支画不透明黑矩形 |
| 黑/视频闪烁 | 上述"填黑"每帧执行，把"保持上一帧"覆盖掉 | 增加 `AnyUploadDone`：仅首次失败填黑，之后 `return false` |
| 音频无声 | `-sv` 缺省值 0 → 主音量 0 | `SoundVolume = (sv > 0 ? sv : 100)/100.0f` |
| 音频不推进 | `FxSoundFMOD` 缺 `Update()`，主循环只更新 Wwise | 新增 `Update()` 并每帧调用 |
| 音效被截断 | SWF `GetSampleCount()` 与 FMOD PCM 长度单位不同（44100/11025≈4.4×） | 优先 `getLength(FMOD_TIMEUNIT_PCM)`，长度不可信时不 `setDelay` |

## 6. 最终配置

- `shouldRenderFilters()`：**仅 `Filter_Shadow`（单 pass 投影）返回 true**，其余（Blur / Glow / Bevel / Gradient* / ColorMatrix …）跳过。依据：Shadow 在 9-1-A 正确且稳定；多 pass 类型在 9-1-B 反馈动画中会让设备在 `Present` 时消失。
- 调试开关全部清除（`GFX_MATRIX_TRACE / GFX_TEXLIFE / GFX_MESH_TRACE / GFX_MASK_TRACE / GFX_TRACE_BATCH / GFX_D3D12_TRACE`）。
- 构建：`MSBuild "…GFx 4.5.32 Leslie Demo.slnx" /t:Build /p:Configuration=D3D12_Debug_Static /p:Platform=x64 /m`。

## 7. 已知遗留

1. **多 pass 滤镜**：9-1-B 反馈动画中 `presentFrame → Present` 处设备丢失；`temp-RT / fence` 生命周期问题（与后来 Vulkan 侧修掉的是同一类）。复现：9-1-B 答完 4 题。
2. **id=654 CopyDescriptors "CPU write only"**：源/目的都在同一 SHADER_VISIBLE 堆内且不重叠，渲染结果正确，判定为 Debug Layer 误报；彻底消除需让每个 Texture 独占 8 个连续 SRV。
3. **PlayerTiny 的 D3D12 配置**编译失败（`dxgitype.h` 重复定义），与本项目无关，仅影响"整个 solution 全部成功"。
4. **窗口刚启动、视频角色尚未创建时**仍会短暂露出 SWF 舞台绿底；彻底解决需覆盖 movie 背景色（`MovieDef` 没有直接 `SetBackgroundColor`）。

## 8. 经验总结

1. **一个悬垂链表能伪装成十几个 bug。** 先修"真根因"（Texture 析构摘链），再谈其它；否则每个崩溃点都只是症状。
2. **改类成员必须删 Obj 重编。** ABI 不一致的症状是"随机渲染错误 + 堆损坏"，且会被误判为 mask/filter/字体/格式问题。
3. **PageHeap 对自定义堆无效。** Scaleform 的 `HeapMH` / MeshCache / MatrixPool 都走自定义页，PageHeap 抓不到；要开自家堆调试或用哨兵副本。
4. **cdb 用法**：`cdb -z dump -c ".ecxr; kb 40"` 足够，`!analyze -v` 太慢；给资源 `SetName` 能让 Debug Layer 消息直接点名。
5. **把随机崩溃变成一条日志**（SEH 包裹可疑写入）是有效的降噪手段，但只是手段，不是修复。
6. **跨后端对照**：D3D1x 的同名实现（Texture 析构、CreateTempRenderTarget 的 `Ptr` 用法）是最快的"正确答案"来源；本次 D3D12 与后来的 Vulkan 都靠它定位。
