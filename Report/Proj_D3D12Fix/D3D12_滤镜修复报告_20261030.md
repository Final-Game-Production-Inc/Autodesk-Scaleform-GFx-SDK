## 1. 摘要

本轮从“9-1-B 四个数字不发光”入手，最终修掉的是 **D3D12 的 SWF 滤镜（Glow 等多 pass 模糊）路径**。问题不是单点，而是 D3D12 后端在资源生命周期、资源状态、描述符回收、常量环、滤镜 pass 组织这五类上的系统性缺失；逐一对照 D3D1x / Vulkan 补齐后，画面与稳定性同时恢复。

- 现象 P1：四个数字只有白/灰描边，没有彩色光晕（Ruffle 与 D3D11 都有）。
- 现象 P2：答完四题进入“顺利通过”后 2~5 秒，`DXGI_ERROR_DEVICE_HUNG`，有时进程直接 AV 在 NVIDIA 驱动内。
- 根因 R1~R8 见第 3 节；修复 F1~F9 见第 4 节；验证见第 5 节。

最终效果：

- `verify_d3d12\D3D12_options_glow_fixed.png` —— 四个选项的彩色光晕与 D3D11 参考一致；
- `verify_d3d12\D3D12_顺利通过_singlepass_fixed.png` —— “顺利通过”横幅、渐变字、缎带、勾选全部正确。

## 3. 现象与根因

### P1：四个选项不发光

D3D12 下四个数字只有白/灰描边、没有彩色光晕；D3D11 与 Ruffle 都有。
9-1-B 的四个数字各带 **两个 GlowFilter**，属于 blur 家族多 pass 滤镜，走 `requireSource`（Target_Original 临时 RT + ping-pong）。

根因（按发现顺序）：

| 编号 | 根因 | 证据 |
|---|---|---|
| R1 | `IsFilterCachingSupported()` 未重写，默认 true。缓存结果被 cacheable prepare pass 占用，但 `drawCachedFilter` 从不消费 → 滤镜不显示 | 与 Vulkan 2026/10/29 22:05 根因 1 同源 |
| R2 | `shouldRenderFilters()` 只放行 `Filter_Shadow`（10/27 的临时护栏），Glow 被整块跳过 | 代码审查 |
| R3 | 临时 RT 用 `PRT_NoSet` 弹出后未从 `RENDER_TARGET` 过渡到 `PIXEL_SHADER_RESOURCE`，下一 pass 采样到未定义数据 | 光晕为空；加过渡后恢复 |
| R4 | 资源状态未跟踪：`transitionRenderTarget` 用固定 before 值；`UpdateData` 每次把状态重置为 RT（复用的临时 RT 只是补 DS），导致 `SRV→RT` barrier 被跳过 | validation `id=538/527`（`ClearRenderTargetView` 在 SRV 状态执行） |

### P2：“顺利通过”TDR

进入反馈动画后 2~5 秒 `hr=0x887A0005 removed=0x887A0006`；有时进程 AV 在 `nvwgf2umx!...`（`OMSetRenderTargets` 内，读 0x28），栈顶为 `HAL::PushRenderTarget`。

根因：

| 编号 | 根因 | 证据 |
|---|---|---|
| R5 | 帧内销毁命令列表仍在引用的资源（临时 RT/DS 在 `EndFrame` evict 时释放） | validation `id=921`（Close/Execute 时报告资源已删除） |
| R6 | `Texture::~Texture` 只延迟释放 resource，未归还 SRV/RTV 描述符索引；横幅缩放不断产生新尺寸临时 RT → 索引只增不减 → 堆外描述符 | 驱动 AV 形状；堆游标打点 |
| R7 | 同一帧内复用刚释放的临时 RT（`RBCL_Reuse_ThisFrame`），而 GPU 尚未执行该帧命令列表 | Vulkan 用 `PendingTargetReleases` 延迟一帧，D3D12 没有 |
| R8 | 多 pass 模糊的“渲染进临时 RT → 下一 pass 立刻采样同一张 RT”往返，在反馈重建帧（`Timeline_16 frame114 → gotoStart → 重新 addChild` 带 Glow 控件）挂 GPU | 二分：跳过 blur 或 shadow 任一 pass 即稳定；单 pass 化后 3/3 稳定 |

排除过的方向（均有实验记录）：

- validation `527/538/921` 全 0 时仍会挂 → 不是 barrier/删除问题单独导致；
- `GFX_FILTER_MAXBLUR=2` 仍挂 → 不是 blur 采样量；
- `GFX_FILTER_NODS=1` 仍挂 → 不是 DS 生命周期单独导致；
- 反馈环检测（采样目标 == 当前 RT）未触发；
- 常量探针 `GFX_D3D12_UNIPROBE=1`：`fsize` 的 `Location=0 / ShadowOffset=960 / Size=4` 与 D3D1x 一致，CPU 值与写入 frag CB 的值逐位相同（0~3.5，循环 ≤8 次）→ 不是 uniform/循环失控；
- 干净重建（删 Obj/ABI）后仍复现 → 不是脏构建；
- `GFX_D3D12_NOCACHEBMP=1` 仍挂 → 不是 cacheAsBitmap。

## 4. 修复清单

> 行号以 2026-10-30 最终源码为准。

### F1 关闭滤镜缓存（对应 R1）

`Src/Render/D3D12/D3D12_HAL.cpp:1277`

```cpp
bool HAL::IsFilterCachingSupported() const
{
    static const bool sFilterCache = Render::IsDebugEnvSet("GFX_D3D12_FILTER_CACHE");
    return sFilterCache;   // 默认 false：每帧重建滤镜
}
```

### F2 放开滤镜种类（对应 R2）

`Src/Render/D3D12/D3D12_HAL.cpp:1361`

- 默认放行全部滤镜；
- `GFX_D3D12_NOFILTERS=1` 回退“无滤镜”基线；
- `GFX_D3D12_FILTER_ALLOW=shadow,glow` 按类型二分；
- `GFX_D3D12_FLTLOG=1` 每个被滤镜图元打印 `[D3D12FLT]`（类型/面积/blur/passes/mode）。

### F3 资源状态跟踪 + 正确过渡（对应 R3、R4）

- `RenderTargetData` 新增 `D3D12_RESOURCE_STATES ResourceState`（`Src/Render/D3D12/D3D12_HAL.h`），只在**资源指针变化**时重置；
- `transitionRenderTarget()`（`D3D12_HAL.cpp:872`）按记录状态发 barrier，跳过冗余；
- `PopRenderTarget()`（`D3D12_HAL.cpp:999`）无论 `PRT_NoSet` 是否设置，都把弹出目标过渡到 SRV；
- 新增 `HAL::drawFilter()` 重载（`D3D12_HAL.cpp:1100`）：本 pass 要采样的 source/original 在绘制前过渡到 SRV，且**先解绑 RTV** 再过渡（规范要求），目标 RT 跳过；
- `SetMainRenderTarget()` 把交换链缓冲状态设为 `PRESENT`。

### F4 帧内不销毁在飞资源（对应 R5）

- `Src/Render/Render_HAL.h/.cpp`：新增 `HAL::DefersBufferManagerEndFrame()`（D3D12 返回 true），
  `RenderBufferManager::EndFrame()` 改到下一帧 `BeginFrame`（平台已等过 fence）执行；
- `Src/Render/D3D12/D3D12_Texture.cpp:256` `Texture::~Texture()`：resource 不再立即 Release，统一压入
  `D3DTextureKillList`，由 `TextureManager::BeginFrame()` 在 fence 之后统一释放；
- `D3D12_Texture.cpp:526` `Texture::ReleaseHWTextures()`：任何线程/任何路径都改为延迟队列（原先渲染线程直接 `Release()`）；
- `D3D12_Texture.cpp:788` `DepthStencilSurface::~DepthStencilSurface()`：DS resource 同样延迟；
- `D3D12_Texture.cpp:1338` `processTextureKillList()`：修掉“手动 Release + Ptr 再 Release”的二次释放；
- `PopRenderTarget()` 摘 DS 时也把 DS resource 压入 kill list。

### F5 描述符索引回收（对应 R6）

`Texture::~Texture()` 现在同时 `freeSRVDescriptor` / `freeRTVDescriptor`，并清空 `SRV/RTV/GPU` 句柄；
三个 `alloc*Descriptor` 增加越界保护与 `[D3D12] RTV/SRV/DSV heap exhausted` 日志，避免写出堆外。

### F6 临时目标整体退役（对应 R7）

对齐 Vulkan `DeferredTargetRelease` / `PendingTargetReleases`：

- `D3D12_HAL.h`：新增
  ```cpp
  struct DeferredTargetRelease { Ptr<RenderTarget> pTarget; Ptr<DepthStencilBuffer> pDepthStencil; };
  Array<DeferredTargetRelease> PendingTargetReleases;
  ```
- `PopRenderTarget()`：临时目标 pop 时 capture DS 并 `PushBack`；
- `BeginFrame()`（`D3D12_HAL.cpp:355`）：fence 之后按 Vulkan 顺序退役：
  `pDepthStencil = 0` → `pTarget->SetInUse(RTUse_Unused)` → `pTarget = 0` → `Clear()`；
- `ShutdownHAL()` / `PrepareForReset()` 先 `Clear()`，避免 `RenderBufferManager::Reset` 的 in-use 断言（0x80000003）；
- `Render_Buffer.h` 新增 `AllowsSameFrameReuse`（D3D12 置 false），`Render_BufferGeneric.cpp:356`
  `reserveSpace()` 跳过 `RBCL_Reuse_ThisFrame` 匹配；`AllowsDeferredBufferRelease = true`。

### F7 多 pass 模糊改单 pass（对应 R8，P2 的直接修复）

`Src/Render/D3D12/D3D12_Shader.cpp:269`

```cpp
unsigned ShaderManager::SetupFilter(const Filter* filter, unsigned fillFlags,
                                    unsigned* passes, BlurFilterState& leBlur) const
{
    const unsigned passCount = Base::SetupFilter(filter, fillFlags, passes, leBlur);
    if (passCount <= 1 || filter->GetFilterType() > Filter_Blur_End)
        return passCount;
    static const bool sMultiPass = Render::IsDebugEnvSet("GFX_D3D12_MULTIPASS_BLUR");
    if (sMultiPass)
        return passCount;
    passes[0] = passes[passCount - 1];   // 折叠成最后的 shadow/glow pass
    return 1;
}
```

最后一个 pass（`ST_SColorOuterBevel` 系列）本身就在一个 2D 循环里完成整幅模糊，因此**画面语义不变**，
但不再产生“渲染完立刻采样”的中间临时 RT。低端平台同样是单 pass 模糊。
`GFX_D3D12_MULTIPASS_BLUR=1` 可复现旧路径。

### F8 共享层防御（真实 AV 点）

- `Src/Render/Render_HAL.cpp:1257` `HAL::PushFilters()`：
  - `CreateTempRenderTarget` 返回 0 时降级为“不滤镜”，不再解引用空 target；
  - `AreaMatrixCount()==0` 的 primitive 不进入滤镜路径（`GetAreaMatrix()` 无越界检查，曾 AV）；
- `Src/Render/Render_ShaderHAL.h:1228` `profilerDrawCacheablePrimArea()`：同样检查面积矩阵；
- `Src/Render/Render_ShaderHAL.h` `drawUncachedFilter()` 结束处补 `applyDepthStencilMode(DepthStencil_Disabled, 0)`，
  避免滤镜/遮罩的 stencil 状态泄漏到后续图元（勾选动画被裁掉的问题）。

### F9 常量环按帧复位（D3D12 规范）

`Src/Render/D3D12/D3D12_HAL.cpp:1667` `MapUniformBuffer()` 原实现：2MB、在 `BeginScene` 复位。
D3D12 的常量在命令列表**执行时**才读取，后一个 scene 会覆盖前一个 scene 的常量 → 滤镜 shader 可能读到垃圾 `fsize`。

修复：16MB（2048 draw/帧）、只在 `BeginFrame`（过 fence 后）复位一次，回绕时打印
`[D3D12] uniform ring wrapped`。

## 8. 遗留与后续两点

### 8.1 多 pass 模糊路径仍是“已知隐患”，未彻底根因化

P2 的**直接修复**是把 D3D12 的模糊类滤镜折叠成单 pass（F7），这与低端平台策略一致、画面语义不变。
但“渲染进临时 RT → 下一 pass 立刻采样同一张 RT”这条多 pass 往返，在 D3D12 + 当前 NVIDIA 驱动上仍会偶发挂 GPU：

- 复现：`GFX_D3D12_MULTIPASS_BLUR=1` + 9-1-B 答完四题；
- 已排除：validation 527/538/921、描述符堆耗尽、同帧复用、退役顺序、DS 生命周期、反馈环、ABI、uniform/循环；
- 下一步方向（换 GPU/驱动或想恢复可分离模糊时）：用 RenderDoc 抓“设备移除前最后一帧”，
  看中间 pass 的 RTV/DSV 与 SRV 是否同一资源、以及该 PSO 的 depth/stencil 状态。

**结论：默认保持单 pass；不要在没有新证据前把 `GFX_D3D12_MULTIPASS_BLUR` 当默认打开。**

### 8.2 调试设施保留，收尾时统一清理

本轮为定位加了一批 env 开关（第 7 节）和少量探针代码，默认零开销，但属于临时设施：

- 位置：`D3D12_HAL.cpp`（FLTLOG/RTDBG/UNIPROBE 之外的 trace）、`D3D12_Shader.cpp`（Finish 探针）、

## 9. 经验（可复用的排查顺序）

1. **先对齐参考后端**：D3D1x 的 `Texture::~Texture`、`PopRenderTarget`、`PopFilters` 是行为基线；Vulkan 的
   `DeferredTargetRelease`/`DrainFrameResources` 是“延迟退役”的参考实现。
2. **D3D12 没有运行时引用跟踪**：任何 `Release` 都必须问“命令列表是否还在用”；销毁统一走 fence 之后的 kill list。
3. **资源状态要自己记**：`ResourceState` 必须随资源指针变化重置，不能每次 `UpdateData` 都当作 RT。
4. **描述符索引也是资源**：`~Texture`/`~DepthStencilSurface` 必须归还 SRV/RTV/DSV，否则长时间播放必然堆外。
5. **ABI 是隐形杀手**：改类成员/虚表后删 Obj 全量重编，否则“玄学渲染错误 + 驱动 AV”。
6. **二分优于猜测**：`SKIP_BLUR`/`SKIP_SHADOW`/`FORCE_PASSES` 三个开关直接把问题压到“多 pass 临时 RT 往返”，
   比继续猜 uniform/barrier 快得多。
7. **探针要打印 CPU 与 GPU 两侧的值**（`UNIPROBE`），只看 CPU 侧无法排除“写错偏移”。
